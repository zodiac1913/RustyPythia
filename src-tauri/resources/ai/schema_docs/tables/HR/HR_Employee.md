# HR.HR_Employee

Primary employee reference table and broad denormalized employee snapshot. It combines identity, contact, organization, employment, position, pay, and other employee attributes.

This is a working business description, not an authoritative HR definition. The database has no table- or column-level `MS_Description` metadata; field meanings below are inferred from names and should be validated with HR subject-matter experts.

## Snapshot

- Schema: HR
- Table: HR_Employee
- Priority: high
- Primary key: EmployeeIdentifier
- Column count: 191
- Schema metadata checked: 2026-10-06

## Usage Notes

- Treat this as the main employee lookup before widening to supporting HR tables.
- For most employee questions other than employee actions, start here because the table already carries a wide denormalized set of employee and organization fields.
- UserIdentifier is the most important conventional join back to CORE.User even if the database does not enforce it with a foreign key.
- If the user starts with a component acronym or admin code, resolve the component in HR.HR_Component first, then use the resulting component context to filter or interpret HR.HR_Employee rows.
- Because the table is denormalized, many fields duplicate context that may also exist elsewhere in HR support tables.
- Treat values as a broad employee snapshot; use HR.HR_EmployeeHistory for prior snapshots and HR.HR_PersonnelAction for personnel actions.
- This table contains sensitive personal and employment data, including direct identifiers, contact details, compensation, and demographic attributes. Do not return sensitive values in user-facing results; follow the PII rules in the global prompt.

## Field Group Guide

The column inventory below is verified against the database schema. These groupings are name-based and are a starting point for business validation, not confirmed definitions.

- **Employee identity and names:** EmployeeIdentifier, PersonnelNumber, CommissionedCorpsSerialNumber, UserIdentifier, and the employee name fields.
- **Contact and location:** MailStop, address fields, WorkLocation, work phone, and Email.
- **Manager snapshot:** IsManager, HasManagerRole, manager identifiers, and manager name, title, phone, and email fields.
- **Organization placement:** Component, Office, Group, and Division identifiers, names, acronyms, admin codes, and ComponentEffectiveDate; also DetailComponentIdentifier and DetailOfficeIdentifier.
- **Employment and service dates:** SeparatedDate, career/service dates, appointment dates, grade/probation dates, and pay-period dates.
- **Pay and position:** BaseHours, salary and locality amounts, hourly/overtime rates, grade, step, job series, pay plan/basis, position number, and position attributes.
- **Code/description pairs:** Many HR classification fields have a companion `Description` column; confirm each code's source and allowed values before interpreting it.
- **Demographic and preference attributes:** Race/ethnicity, sex, citizenship, veteran, handicap, and related fields; these require especially careful handling.
- **Location and routing attributes:** Latitude/longitude, distance, route-step, building, and `Ads*` fields; the specific meaning and source of the `Ads*` prefix need confirmation.
- **Lifecycle and audit fields:** DeactivateTimeStamp, DeleteTimeStamp, AddUserIdentifier, AddTimeStamp, LastUpdateUserIdentifier, and LastUpdateTimeStamp.
- **Remote-work/locality attributes:** EmployeeRemoteWorkSelection, LocalityArea, LocalityAreaDescription, and TourType fields; confirm the organization's definitions.

## Conventional Joins

- Join to CORE.User on UserIdentifier when user-account context is needed.
- Use component-related columns together with HR.HR_Component when the question is about org placement, acronym lookup, admin code lookup, or rollups.

## Inbound Foreign Keys

- FK_HR_EmployeeHistory_HR_Employee: HR.HR_EmployeeHistory via EmployeeIdentifier -> EmployeeIdentifier
